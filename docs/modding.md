# Как сделать мод

Мод добавляет в игру блоки и предметы (JSON и картинки), задаёт предметам поведение на C#, реагирует на события мира и может явно заменить чужое определение. Код игры при этом не меняется. Готовый пример — [`examples/ExampleMod`](../examples/ExampleMod): аметистовая руда, волшебная палочка, награда за руду и новая текстура песка.

Название игры временное (`Sandbox`); ниже оно встречается в путях и именах сборок.

## 1. Где лежат моды

Папка модов общая для всех миров:

- Windows: `%LOCALAPPDATA%\Sandbox\Mods\`
- Linux: `~/.local/share/Sandbox/Mods/`

Игра создаёт её при первом запуске. Каждый мод — отдельная папка внутри, **имя папки = id мода**. Другую папку модов можно указать аргументом запуска `--mods ПАПКА` — удобно при разработке: `Sandbox --mods путь/к/папке/с/модами`.

```
Mods/
  my_mod/
    mod.json                 обязательно
    content/                 блоки и предметы (JSON), можно без неё
      blocks/marble.json
      items/marble.json
      items/chisel.json
    textures/blocks/         картинки блоков, PNG 16×16
      marble.png
    textures/items/          картинки предметов, PNG 16×16
      chisel.png
    MyMod.dll                код мода, можно без него
```

## 2. mod.json

```json
{
  "id": "my_mod",
  "name": "Мой мод",
  "version": "1.0.0",
  "dependencies": { "base": "1.0" },
  "assembly": "MyMod.dll"
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `id` | да | a–z, 0–9, `_`; совпадает с именем папки. Это же **пространство имён** всего, что объявляет мод: `my_mod:marble`. `base` занят игрой |
| `name` | да | название для людей |
| `version` | да | `1.0`, `1.2.3` |
| `dependencies` | нет | моды, без которых этот не работает: `"id": "наименьшая версия"`. Ванильный контент — мод `base` версии 1.0.0 |
| `assembly` | нет | имя DLL с кодом в папке мода. Без него мод — только данные |

Моды загружаются по зависимостям (сначала те, от кого зависят), при прочих равных — по алфавиту id. Нет нужного мода, мала его версия, циклическая зависимость, неизвестное поле — игра не запускается и пишет одну строку `[Mods] Мод '<id>': …` с причиной.

## 3. Блоки и предметы (content/)

Один JSON-файл — одно определение; папки внутри `content/` — как удобно. Неизвестное или повторённое поле, неверный тип — ошибка запуска `[Content] … Файл '<мод>/…': …` с путём и полем.

### Блок

```json
{
  "type": "block",
  "name": "my_mod:marble",
  "isOpaque": true,
  "isSolid": true,
  "textures": "marble"
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `name` | да | `<id мода>:имя` — только своё пространство имён (чужое — см. «Замена») |
| `isOpaque` | да | закрывает соседние грани (непрозрачный полный куб) |
| `isSolid` | нет, `true` | в блок упираются тела |
| `hardness` | нет, `1` | секунды ломания рукой (если блок добывается рукой); `0` — ломается сразу |
| `tool` | нет | вид инструмента, который ломает быстрее: `pickaxe`, `axe`, `shovel` или свой (a–z, `_`) |
| `toolTier` | нет, `0` | нужный уровень инструмента вида `tool`, чтобы блок что-то дал (дерево 1, камень 2, медь 3). Без него — в 10/3 раза дольше и без добычи |
| `textures` | нет | строка — одна картинка на все грани; объект `{"top": …, "side": …, "bottom": …}` — по граням. Без поля блок будет в шахматку «нет текстуры» |

Имя текстуры — имя PNG без расширения. Короткое имя (`"marble"`) ищется в своём моде: `textures/blocks/marble.png`. Полное (`"base:stone"`) — у указанного мода; у `base` это ванильные картинки. Так можно взять ванильную текстуру для одной из граней.

### Предмет

```json
{
  "type": "item",
  "name": "my_mod:marble",
  "maxStackSize": 64,
  "placesBlock": "my_mod:marble",
  "displayName": "Мрамор"
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `name` | да | `<id мода>:имя` |
| `maxStackSize` | да | сколько штук в одном слоте |
| `placesBlock` | нет | какой блок ставит предмет (любого мода). Первый предмет, ставящий блок, выпадает из этого блока при ломании |
| `behavior` | нет | что предмет делает по ЛКМ/ПКМ — имя поведения (раздел 5). По умолчанию `base:place_block` у предмета с `placesBlock` (ЛКМ ломает, ПКМ ставит блок) и `base:hand` у остальных (ЛКМ ломает) |
| `displayName` | нет | название для игрока; без него показывается `name` |
| `icon` | нет | картинка предмета (см. ниже) |
| `tool` | нет | предмет — инструмент: `{"type": "pickaxe", "tier": 2, "speed": 4}` — вид, уровень и во сколько раз быстрее руки он ломает блоки своего вида. Поведение по умолчанию — `base:hand` (ЛКМ ломает, как рука) |

Картинка предмета — поле `"icon": "chisel"`: файл `textures/items/chisel.png`, 16×16, прозрачный фон допустим. Имя дополняется так же, как у текстур блоков (`"base:…"` — картинка другого мода). Без `icon` предмет, ставящий блок, рисуется кубиком этого блока, остальные — квадратом «нет текстуры».

**Блок без предмета** в мире есть, но ломается «в никуда». Обычно блоку нужен одноимённый предмет с `placesBlock`.

## 4. Проект C#

Код мода — библиотека .NET 10. Она ссылается на две сборки игры: `Sandbox.Api.dll` (интерфейсы для модов) и `Sandbox.Shared.dll` (общие типы: `BlockId`, `ItemStack`, `Inventory`…). Обе лежат рядом с игрой. **Копировать их в папку мода нельзя**: игра всегда даёт свои, иначе мод не загрузится.

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <AssemblyName>MyMod</AssemblyName>
    <!-- Собственные NuGet-зависимости мода копируются к нему -->
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <!-- Папка игры (где Sandbox.Api.dll) -->
    <GameDir>путь/к/игре</GameDir>
  </PropertyGroup>

  <ItemGroup>
    <Reference Include="Sandbox.Api" HintPath="$(GameDir)/Sandbox.Api.dll" Private="false" />
    <Reference Include="Sandbox.Shared" HintPath="$(GameDir)/Sandbox.Shared.dll" Private="false" />
  </ItemGroup>

</Project>
```

`dotnet build` кладёт `MyMod.dll` в `bin/Debug/net10.0/`; скопируйте в папку мода её и `MyMod.deps.json`, а если мод использует NuGet-пакеты — и их DLL оттуда же (`Sandbox.*.dll` там не будет: `Private="false"`). Можно настроить вывод сразу в папку мода — так сделано в `ExampleMod.csproj`.

### Точка входа

В сборке должен быть **ровно один** открытый класс, реализующий `IMod`, с конструктором без параметров. Игра найдёт его сама и вызовет `Load` один раз при запуске — после загрузки всего контента и до первого тика.

```csharp
using Api;

public sealed class MyMod : IMod
{
    public void Load(IModContext context)
    {
        var stone = context.Blocks.Get("base:stone").Id;
        var marble = context.Blocks.Get("my_mod:marble").Id;

        context.RegisterItemBehavior("my_mod:chisel", new ChiselBehavior(stone, marble));
        context.Events.OnBlockPlaced(e => context.Log($"{e.Player.Name} поставил блок в {e.Position}"));
        context.Log("загружен");
    }
}
```

`IModContext`:

| Член | Что делает |
|---|---|
| `ModId` | id мода |
| `Blocks`, `Items` | реестры всего контента (всех модов), уже загруженные: `Get("мод:имя")` даёт определение и его `Id` |
| `RegisterItemBehavior(id, behavior)` | поведение предмета под именем `<id мода>:имя` |
| `Events` | подписка на события мира |
| `Log(text)` | строка в лог игры: `[Mod my_mod] text` |

Регистрировать и подписываться можно **только в `Load`**. Исключение в `Load` — ошибка запуска `[Mods] Мод 'my_mod': ошибка в IMod.Load: …`.

Код модов исполняется на сервере игры (в одиночной игре — в том же процессе, в потоке сервера) и с полным доверием, как в tModLoader и Vintage Story. Числовые id (`BlockId`, `ItemId`) действуют только в текущем запуске — между запусками и в своих файлах храните имена.

## 5. Поведение предметов

```csharp
using Api;
using Shared.Blocks;
using Shared.Items;

internal sealed class ChiselBehavior(BlockId stone, BlockId marble) : IItemBehavior
{
    public void Use(ItemAction action, in ItemUseContext context)
    {
        if (action != ItemAction.Primary || context.Target is not { } target)
            return;
        if (context.World.GetBlock(target.Block) == stone)
            context.World.TrySetBlock(target.Block, marble);
    }
}
```

Предмет ссылается на поведение в своём JSON: `"behavior": "my_mod:chisel"`. Ссылка на незарегистрированное поведение — ошибка запуска.

Ломание удержанием ЛКМ — через `context.Breaker.StartBreaking(pos)`: время по твёрдости блока и инструменту в руке считает сервер, он же отменяет ломание (игрок отпустил кнопку, сменил предмет, отошёл) и выдаёт добычу. Так ломают ванильные `base:hand` и `base:place_block`. Сразу, без удержания, — `context.World.TryBreakBlock`.

`ItemUseContext`: `World` (мир), `Items` (реестр предметов), `Player` (кто применил), `Breaker` (ломание удержанием), `Target` (блок под прицелом — `Block` и грань `Normal`, или `null`), `EyePosition`; для удобства `Inventory`, `HeldItem` (предмет в руке) и `InfiniteItems` (творческий режим: ничего не тратить и не выдавать).

`IWorld`:

| Метод | Что делает |
|---|---|
| `GetBlock(pos)` | блок в точке (в незагруженном чанке — воздух) |
| `TrySetBlock(pos, block)` | меняет блок без событий — для превращений, не являющихся действием игрока |
| `TryBreakBlock(pos, player)` | игрок ломает блок: воздух на месте и событие `BlockBroken`. Добычу не выдаёт — это дело поведения |
| `TryPlaceBlock(pos, block, player)` | игрок ставит блок: событие `BlockPlaced` |
| `IsBlockedByPlayer(pos, block)` | стоит ли твёрдый блок поперёк тела какого-нибудь игрока |

Все `Try…` возвращают `false`, если чанк не загружен. Изменения сразу уходят игрокам. Инвентарь игрока (`Player.Inventory`) — авторитетный: `Add`, `Remove`, `Set`; изменения уходят клиенту в конце тика.

## 6. События мира

```csharp
context.Events.OnBlockBroken(e => …);   // e.World, e.Player, e.Position, e.Block (что было на месте)
context.Events.OnBlockPlaced(e => …);   // e.World, e.Player, e.Position, e.Block (что поставлено)
context.Events.OnPlayerJoined(e => …);  // e.World, e.Player
```

- События сообщают об уже случившемся; отменить их нельзя.
- Обработчик вызывается, когда действие закончено целиком (добыча уже в инвентаре), в потоке сервера, по порядку загрузки модов.
- `BlockBroken`/`BlockPlaced` возникают при `TryBreakBlock`/`TryPlaceBlock` — и у ванильных предметов, и у поведений модов, которые ломают и ставят через них.
- Исключение в обработчике пишется в лог (`[Mod my_mod] Ошибка в обработчике BlockBroken: …`) и не мешает ни игре, ни другим модам.
- Обработчик может сам ломать и ставить блоки; цепочка событий за одно действие ограничена 10 000 — бесконечная перекличка модов обрывается с записью в лог.

## 7. Замена чужих определений

Мод может целиком заменить блок или предмет другого мода (в том числе ванильный) — тот же JSON с полным именем и `"override": true`:

```json
{
  "type": "block",
  "name": "base:sand",
  "isOpaque": true,
  "override": true,
  "textures": "sand_rippled"
}
```

- Заменяется **всё** определение: указывайте все нужные поля, а не только изменённые.
- Мод должен зависеть (в `mod.json`, можно через другой мод) от мода, чьё определение заменяет; заменять можно только существующее определение того же типа.
- Если одно имя заменяют несколько модов, каждый следующий должен зависеть от предыдущего — побеждает последний. Два независимых мода, заменяющих одно имя, — ошибка.
- Имя не меняется, поэтому старые миры открываются как обычно. Если замена уменьшила `maxStackSize`, стопки в сохранении урезаются до нового предела (с записью в лог).

## 8. Проверка и типичные ошибки

Запустите игру с вашей папкой модов и смотрите консоль:

```
[Server] Моды: my_mod 1.0.0
[Mod my_mod] загружен
```

| Сообщение | Что не так |
|---|---|
| `[Mods] Мод 'x', mod.json: id 'y' должен совпадать с именем папки мода` | переименуйте папку или id |
| `[Mods] Мод 'x' требует мод 'y', которого нет в папке модов` | положите зависимость или уберите её из `dependencies` |
| `[Mods] Мод 'x': в сборке … нет класса, реализующего IMod` | нет открытого класса `IMod` или он абстрактный |
| `[Mods] Мод 'x': типы сборки не загрузились` | мод собран против другой версии `Sandbox.Api.dll` — пересоберите |
| `[Content] … Файл 'x/…': имя 'base:…' не из пространства имён пакета 'x'` | своё определение — `x:…`; чужое — только с `"override": true` |
| `[Content] Предмет 'x:…' ссылается на неизвестное поведение 'x:…'` | поведение не зарегистрировано в `Load` или опечатка в `behavior` |
| `[Client] Нет текстуры x:…: …/textures/….png` | нет картинки — блок или предмет будет в шахматку |
| `[Client] Текстура x:… — 32×32, нужна 16×16` | все текстуры и картинки — 16×16 |

Если мир открыть без мода, с которым в нём играли, игра предупредит: блоки мода станут воздухом, его предметы пропадут из инвентарей.

## Пока нельзя

Свои экраны и отрисовка на клиенте, отменяемые события, свой код каждый тик, частичная правка чужих определений (только замена целиком), выгрузка и перезагрузка модов без перезапуска игры, переводы.
