# Проверка графики этапа 7 — 2026-10-24

Кадры получены реальными классами `ItemEntityRenderer` и `Hud` в отдельном временном C# harness через EGL pbuffer, без окна и игрового мира. Контекст: EGL 1.5, OpenGL 4.6 core, Mesa 26.2.5, **llvmpipe (LLVM 23.1.3, 256 bits)** — программный рендер. Это проверка OpenGL-пути и раскладки интерфейса, а не прохождение игры и не замер Intel Iris Xe.

При первоначальной проверке приложения доступ был ограничен: Wayland не позволяет подключиться к дисплею, niri IPC возвращает EPERM, `/dev/uinput` отсутствует.

## Кадры

- `items.png`: настоящий инстансный рендер двух предметов одним вызовом, с текстурами дёрна и палки; чёрный фон тестового буфера. Два экземпляра, `glGetError = NoError`, 740 непустых пикселей слева (куб) и 132 справа (палка). Прозрачные пиксели картинки не закрашивают фон.
- `health-1280.png`, `health-800.png`: HUD в размерах 1280×720 и 800×600, соответственно масштабы 3 и 2, здоровье 7/20 (три полных сердца и половинка), палка ×12. Голубая заливка заменяет мир.
- `death-1280.png`, `death-800.png`: экран смерти в тех же размерах, с наведением на кнопку возрождения. Это вызов `Hud.DrawDeath`, без серверного цикла.

Все семь кадров просмотрены: текст чёткий, имя предмета, сердца и хотбар не пересекаются; заголовок, объяснение и кнопка смерти помещаются в экран. Интерактивная обработка клика и блокировка управления проверяются автотестами `HealthViewTests`, а не этими статичными кадрами.

## Метод

Временный harness расположен в `/tmp/sandbox-egl-check` текущей рабочей сессии и не является постоянным инструментом проекта. Он ссылается на `Client.csproj` под именем friend assembly `Sandbox.Client.Tests`, получает surfaceless-дисплей `eglGetPlatformDisplay(EGL_PLATFORM_SURFACELESS_MESA)`, создаёт pbuffer 1920×1080 и OpenGL core 4.6 через `libEGL.so.1`, а функции OpenGL передаёт в Silk.NET через `eglGetProcAddress`.

Данные загружаются через настоящий `GameContent.Load`, `BlockVisuals`, `ItemVisuals`, `TextureFiles` и `TextureArray`. Для предметов используются `ClientEntities` с двумя `EntitySpawned`, затем обычный `ItemEntityRenderer.Draw`; проверяются число видимых экземпляров, отсутствие GL-ошибки и непустые пиксели в обеих половинах кадра. HUD использует штатный Press Start 2P и реальные методы рисования. После `glFinish` кадры читаются `glReadPixels`, сохраняются PPM и преобразуются в PNG без масштабирования.

Команды harness (пока существует временная папка):

```sh
dotnet build /tmp/sandbox-egl-check/egl.csproj --no-restore -m:1 -nr:false -p:NuGetAudit=false
/tmp/sandbox-egl-check/bin/Debug/net10.0/Sandbox.Client.Tests
python /tmp/save-stage7-images.py
```

Дополнительно в той же проверке: `health-1920.png` и `death-1920.png` — 1920×1080, масштаб 4. Замер 1000 видимых кубиков в 1280×720, 10 кадров прогрева и 50 измерений `Clear + Draw + glFinish`: медиана **3,488 мс**, минимум 3,104, максимум 4,141 мс; GL NoError. Сцена предметов без мира, программный llvmpipe, Debug; сравнивать с FPS всей игры на Iris Xe нельзя.
